# Рішення 02 — ліміт розміру

**Рішення:** помірно підняти бюджети в `.size-limit.json` один раз, у кроці 4 (перший, що його перевищить): `Styles` 12 → 15 KB, `Full bundle` 195 → 205 KB. `Core` (180) та `Icons` (30) не міняти. Для `./markdown` (крок 6) і `./code-editor` (крок 9) — окремі JS-записи, як уже сказано в плані: `path` `dist/markdown.js` / `dist/code-editor.js`, той самий `ignore` (+ `/^@codemirror\//` для code-editor), ліміт = виміряний розмір + ~20 % із округленням угору. CSS не урізати.

**Чому:**
- CSS один на всі точки входу (`cssFileName: 'index'`, без code split): стилі `TLogPane`, `TFileTree`, `TPathCrumbs`, `.t-markdown` (крок 6 прямо каже — у `index.css`) і `TLogView` потрапляють у `dist/index.css`. Окремий CSS-бюджет для підточок неможливий без зміни збірки — це не KISS.
- Зараз `Styles` 11.94/12 KB, `Full bundle` 187.92/195 KB — обидва впираються. Кроки 4, 5, 7, 8 додають ~1.5–2.5 KB brotli CSS і ~4–8 KB JS в основну частину; запас +3 KB / +10 KB вистачить до 1.5.0 і лишає ліміт сторожем від випадкового росту.
- Урізання CSS — окрема робота з ризиком регресій вигляду; не входить у план.

**Що змінити і де:**
- Крок 4: `.size-limit.json` — `Styles.limit: "15 KB"`, `Full bundle.limit: "205 KB"`; у звіті кроку — фактичні цифри до/після. Перевірка `npm run check:size`.
- Крок 6: додати запис `"Markdown (opt-in)"` для `dist/markdown.js`.
- Крок 9: додати запис `"Code editor (opt-in)"` для `dist/code-editor.js` (CodeMirror у `ignore`).
- Якщо після кроку 8 знову < 0.3 KB запасу — не піднімати мовчки, а завести нове issue.

**Потрібне рішення власника: ні** (бюджети — внутрішній сторож CI, план уже передбачає правки `.size-limit.json`; публічний API не змінюється).
